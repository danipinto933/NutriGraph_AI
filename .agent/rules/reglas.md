Rules del Proyecto: NutriGraph AI (Workspace Rules)1. Visión del Proyecto y ContextoNutriGraph AI es una plataforma microservicios de recomendación nutricional e inteligencia artificial conversacional (GraphRAG). El sistema registra usuarios, calcula métricas biométricas (IMC, TMB, GETD), gestiona intolerancias alimentarias y ofrece sugerencias de recetas y alimentos filtrados de forma estrictamente determinista mediante una base de datos de grafos (Neo4j) y streaming en tiempo real (SSE).2. Stack Tecnológico ObligatorioBackend (Microservicios en Python)Lenguaje/Framework: Python 3.11+ con FastAPI utilizando programación asíncrona (async/await).Validación y Configuración: Pydantic V2 para la validación de schemas HTTP, contratos de eventos y pydantic-settings para variables de entorno.Autenticación y Seguridad: JWT (JSON Web Tokens) con hashing de contraseñas vía passlib / bcrypt.Base de Datos de Grafos: Neo4j 5.x utilizando el driver oficial de Python (neo4j) y consultas Cypher parametrizadas.Broker de Eventos: Apache Kafka en modo KRaft (sin Zookeeper), utilizando aiokafka para comunicación asíncrona entre servicios.Caché y Memoria LLM: Redis 7 para la memoria de conversación por sesión y caché de consultas frecuentes.Orquestación LLM: LangChain / LlamaIndex con soporte de Tool Calling explícito.Testing: pytest, pytest-asyncio, httpx para peticiones HTTP de prueba y testcontainers-python para tests de integración con instancias reales de Neo4j y Kafka.Frontend (Cliente Web)Framework: Angular (última versión) utilizando Standalone Components, Angular Signals y RxJS para la gestión reactiva de estado.Comunicación en Tiempo Real: Consumo de Server-Sent Events (SSE) con EventSource / fetch asíncrono para renderizar las respuestas del chat token a token.Testing: Jasmine / Jest para pruebas unitarias de componentes y Playwright para pruebas End-to-End (E2E).Infraestructura y GatewayAPI Gateway: Traefik v2.10 (enrutamiento dinámico, reglas de CORS centralizadas, rate limiting).Service Discovery & Config Server: HashiCorp Consul / DNS de Kubernetes/Docker + Vault.Contenedores: Dockerfile multi-stage por microservicio y un orquestador global docker-compose.yml en la raíz.3. Arquitectura y Principios de DiseñoDesacoplamiento Estricto: Los microservicios (user-auth-service, nutrition-graph-service, ai-agent-service) no deben realizar llamadas HTTP directas entre sí si la comunicación puede resolverse de forma asíncrona mediante eventos en Kafka (UserRegistered, UserIntolerancesUpdated).Monorepo Limpio: El código debe estructurarse modularmente manteniendo los límites entre la infraestructura (config/), cada microservicio (services/) y el cliente frontend (frontend/).Punto Único de Entrada: Ningún microservicio debe exponer directamente sus puertos al frontend; todas las peticiones externas deben ser enrutadas a través del API Gateway (Traefik).4. Reglas de Negocio y Dominio NutricionalSeguridad Alimentaria Determinista:El filtrado de alérgenos, intolerancias y restricciones dietéticas (vegana, vegetariana, keto) NUNCA debe dejarse a la inferencia del modelo de lenguaje (LLM).Toda validación debe ser ejecutada mediante traversals lógicos en el grafo Neo4j en Cypher (WHERE NONE(...)), garantizando un 0% de alucinaciones en exclusiones de alérgenos.Modelado en Neo4j (LPG):Nodos: :User, :Recipe, :Ingredient, :Nutrient, :Allergen, :DietType.Ingredientes: Los nodos :Ingredient deben almacenar calorias_100g, proteinas_100g, grasas_100g y carbohidratos_100g.Agregación de Recetas: La sumatoria de calorías y macronutrientes de una :Recipe se calcula dinámicamente multiplicando los valores base del ingrediente por los gramos definidos en la relación :CONTAINS_INGREDIENT.Cálculos Biométricos del Onboarding:IMC: $\text{peso} / (\text{altura en m})^2$.TMB: Ecuación de Mifflin-St Jeor según el sexo del usuario.GETD: TMB multiplicada por el factor de actividad física.5. Estándares de Código y CalidadTipado Estricto: Utilizar type hints de Python en todas las funciones y clases del backend, y TypeScript en modo estricto en el frontend Angular.Manejo de Excepciones: Definir excepciones personalizadas en FastAPI con HTTPException estructuradas y handlers globales.Documentación OpenAPI / Swagger: Todos los endpoints de FastAPI deben incluir descripciones claras, tipos de respuesta (response_model) y códigos de estado HTTP estándar.Pruebas Automatizadas: Todo nuevo endpoint o función crítica de negocio debe incluir su correspondiente test en pytest o test de integración con httpx.
